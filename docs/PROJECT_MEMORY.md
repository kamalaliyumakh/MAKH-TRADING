## Product objective

Build a risk-controlled platform that discovers selected low-priced momentum stocks, validates market and catalyst evidence, supports self-directed paper and controlled-live trading through a broker API, and enforces centralized pre-trade and intraday risk controls.

## Product scope baseline

- Public Angular landing site with product, security, legal/privacy and access-request routes.
- Authenticated Angular portal containing dashboard, scanner, symbol workspace, watchlists, orders, positions, risk console, journal, reporting and administration.
- ASP.NET Core backend organized as Domain, Application, Infrastructure, API and Worker projects.
- PostgreSQL system of record with controlled migrations, immutable risk/order evidence and an outbox.
- Provider-neutral ports for market data, reference data, news/filings, permitted social signals, broker trading and notifications.
- Paper-first delivery with a separately approved limited-capital live pilot.

## Trading baseline

- Initial universe: approved Nasdaq/NYSE-listed common shares; OTC excluded from MVP.
- Default price range: USD 3.00 to USD 7.00.
- Relative volume: at least 3.0 using time-of-day normalization.
- Public float: at most 500,000 shares using a documented vendor definition.
- A 100% to 600% intraday gain is a watch/risk signal only and never standalone order authority.
- Verified catalyst, current executable quote, acceptable spread/liquidity and a valid exit plan are required.
- Central risk approval is mandatory before broker submission.

## Technology baseline

- Angular 22 with strict TypeScript, standalone components, lazy routes and supported production APIs.
- .NET 10 LTS / ASP.NET Core, nullable reference types and asynchronous I/O.
- Clean Architecture modular monolith for the initial release.
- EF Core 10 with Npgsql and PostgreSQL 18.
- REST/OpenAPI for commands and queries; SignalR for recoverable real-time updates.
- OIDC authorization code with PKCE; MFA/step-up for sensitive actions.

## Non-negotiable safety rules

- Paper and live accounts, credentials and visual modes are segregated.
- Risk, authorization or critical data-service failure blocks new entries.
- Every order mutation is idempotent and reconciled against the broker.
- Social signals alone cannot confirm a catalyst or authorize a trade.
- No live credentials, live order, external publication or consequential external action without explicit user authority and the applicable signed gates.
- Existing unrelated repositories and user changes are not modified without explicit scope.
